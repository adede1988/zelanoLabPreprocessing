**Source of truth.** `dataTracking.xlsx` (`R:\Neurology\Zelano_Lab\Lab_Common\Admin\dataTracking.xlsx`,
`Sheet1`, header row 2, data from row 3). A row is identified by `Subject ID` + `Task`; a session normally

`writePreProcX`. The only hand‑edits authorised in this work order are the two in Task 1 (the SP_2 ID fix

**Scope filter (D1).** Only rows with `dataType` = `ephys` are in scope. `ephys_echem` rows are skipped for

finals belonging to `ephys_echem` rows (e.g. `260326_OBE_NWU_AD_2` O15/cue) are left untouched.

**Definitions used throughout**
- *On server* — sheet `Data On Server` = `X` **and** the session folder exists on `R:`.
- *Extracted* — sheet `Raw Data Extracted` = `X` **and** the extracted raw `.mat` exists under
  `<root>\<id>\raw\...` (verify the exact layout against an existing participant — CLAUDE.md §2).
- *Preprocessed* — a final `<root>\<id>\preProc\<id>_<task>preproc.mat` exists on `R:`, loads, and has
  `moreThan1` (breathing‑type tasks: also `bmObj` and `baseEmotion` — a bare intermediate does not count).
- *Current* — a preprocessed final that also has a `behDat.manOnset` column (i.e. produced by the
  post‑July‑2026 pipeline). Pre‑July finals are *preprocessed but stale*.
- The sheet's `Data Preprocessed` column is brought into line with the disk in Task 1 (D2) and from then
  on is set to `X` only by `writePreProcX` after a verified save. Until Task 1 has run, decide "preprocessed"
  from the disk, not the column.

**Parameter states (`paramSource`)**
- `curated` — trusted; run unattended.
- `guess` — parameters exist but are unverified.
- blank on an in‑scope row — no parameters yet: you create a guess and write it with `paramSource=guess`.
- How to guess (D3), in priority order:
  1. If the same `Subject ID` already has a `curated` row for another task (same recording day and montage),
     copy those values. **The new row is still written as `guess`** — inheritance never produces `curated`.
  2. Otherwise use the most common values among curated rows of the same `Type`, then inspect the session
     (`paramCheck` / `paramCheckECG` figures) for the per‑session ones: `rspIDX` (cleanest respiration
     channel), `rspFlip` (inhale must be positive), `beatSpec` (start from the Type's most common spec and
     adjust until beats are detected cleanly).
  3. Type `EEG_breathing` standard set: `rspIDX=1`, `rspFlip` by inspection (curated EEG sessions split
     14:7 between −1 and +1), `hasEEG=true`, `hasMacros=false`, `spikeClean=false`, `spikeThresh=20`,
     `spikeWin=11`, `macroRemove` blank, `beatSpec` start `1,0,gt,3.5`, `isNewStd=true`. There are no
     macro channels in these recordings, so macro/spike settings are inert.
- Whether a `guess` session is **run** (D4):

| 9 breathingTasks_separate (Dupi and OBEControl) | run anyway, leave `guess` |

"Run anyway" means: the batch driver sets an explicit override (e.g. `P.allowGuessRun=true`; never the
default), the pipeline still writes every `paramCheck` / `paramCheckECG` / onset‑QC figure to the session's
figure folder, saves the final, and leaves `paramSource=guess` so the outputs get checked by hand later.
